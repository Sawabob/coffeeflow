# CoffeeFlow — документація REST API

Базова адреса: `http://127.0.0.1:5000/api/v1`. Формат: JSON, UTF-8. Версія API: 1.0.0.
Специфікація OpenAPI: `docs/openapi.json`, також `GET /api/v1/openapi.json`. Її можна імпортувати в Postman або Swagger Editor.

## Cookie та CSRF
1. Виконайте `GET /auth/csrf`, збережіть cookie та поле `csrf_token`.
2. Для POST, PATCH, DELETE надсилайте цю cookie та заголовок `X-CSRFToken`. JSON-запити також потребують `Content-Type: application/json`.
3. Для адміністративних функцій виконайте `POST /auth/login`. Замініть CSRF-токен на новий із відповіді; cookie теж має оновитися.
4. Після виходу чи закінчення години отримайте новий токен. JWT/API-ключ для входу не використовується.

Гість може читати лише замовлення, створені з його cookie. Очищення cookie позбавляє гостя цього доступу; адміністратор зберігає доступ. Адміністративна сесія має строк 8 годин і використовує підписану cookie Flask.

## Загальні правила
- Грошові значення — цілі копійки UAH (6500 = 65,00 грн). Ціна та загальна сума надходять з сервера.
- `pickup_at`: ISO 8601 із UTC offset або Z, від 15 хвилин до 7 днів від поточного часу. Відповідь нормалізована до UTC. Дату в прикладах потрібно замінити на майбутню.
- У JSON невідомі поля відхиляються; true/false не приймаються як цілі числа. Текстові поля обрізаються по краях і не допускають керівних символів.
- Списки: limit 1–100, типово 20; offset 0–1000000, типово 0. Параметри не можуть повторюватися. Невідомі параметри списків дають 422.
- Максимальний розмір тіла — 32 КіБ. Зміни не виконуються через GET. CORS не ввімкнено: фронтенд планується на тому самому origin.
- Ліміт входу: 10 POST /auth/login за 15 хвилин; ліміт замовлень: 30 POST /orders за 15 хвилин. Ключ — IP, ліміти спільні для клієнтів за одним NAT, діють у межах одного процесу, скидаються при перезапуску. Невдалі запити теж враховуються. Інші маршрути спеціального ліміту не мають.
- Повторний POST /orders створює окреме замовлення: ключі ідемпотентності ще не реалізовано.

## Стандартна помилка
```json
{
  "error": {
    "code": "validation_error",
    "message": "Перевірте вхідні дані.",
    "fields": {
      "quantity": "Потрібне ціле число 1–20."
    }
  }
}
```

Коди: 400 — JSON/CSRF; 401 — автентифікація; 404 — ресурс або доступ гостя; 405 — метод; 409 — конфлікт; 413 — розмір; 415 — формат; 422 — валідація; 429 — частота; 500 — внутрішня помилка; 503 — база. Для 429: Retry-After 900, для 503: 1. Помилки маршрутизації мають code `http_<номер>`.
Приклади кодів: `csrf_failed`, `authentication_required`, `invalid_credentials`, `validation_error`, `product_not_found`, `category_not_found`, `order_not_found`, `category_in_use`, `product_unavailable`, `invalid_transition`, `conflict`, `rate_limit_exceeded`, `database_unavailable`, `internal_error`.

## POST /auth/login
Вхід адміністратора. До 10 спроб за 15 хвилин на IP у межах процесу. Після входу використовуйте повернений новий CSRF-токен.
Доступ: гість / відповідна cookie для операцій із замовленнями.

| Поле JSON | Обов’язкове | Тип і правила |
|---|---|---|
| username | так | {"type": "string", "minLength": 3, "maxLength": 40} |
| password | так | {"type": "string", "minLength": 1, "maxLength": 128} |

Приклад тіла запиту:
```json
{
  "username": "admin",
  "password": "Ваш-власний-пароль"
}
```

Успіх: **200**.
```json
{
  "admin": {
    "id": 1,
    "username": "admin"
  },
  "csrf_token": "<новий-токен>"
}
```
Можливі помилки: 400 — CSRF відсутній / неправильний або пошкоджений JSON., 401 — Потрібен вхід або неправильні облікові дані., 413 — Тіло перевищує 32 КіБ., 415 — Очікується Content-Type: application/json., 422 — Помилка валідації., 429 — Перевищено ліміт; Retry-After: 900., 500 — Внутрішня помилка., 503 — База недоступна; Retry-After: 1.
