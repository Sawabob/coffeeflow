# Планування та робота з Git

План охоплює серверну частину, інтерфейс, тестування та документацію. При індивідуальній розробці ці напрями виконує один розробник. Наведені оцінки часу є плановими.

| Завдання | Критерій готовності | Напрям | Орієнтир |
|---|---|---|---|
| Схема SQLite | Таблиці, ключі й обмеження створюються без втрати даних | Back-end | День 1, 2 год |
| Каталог | GET, POST, PATCH, DELETE; захищені зміни | Back-end | День 1, 3 год |
| Адміністративний доступ | Хеш пароля, сесія, CSRF, закриті маршрути | Back-end | День 2, 3 год |
| Замовлення | Серверна ціна, транзакція, час, права доступу, статуси | Back-end | День 2, 4 год |
| Контракт API | Параметри, приклади, помилки, OpenAPI | Документація | День 3, 2 год |
| Тести та звіт | Успішні й негативні сценарії, журнал результатів | Тестування | День 3, 3 год |

## Репозиторій

Код і документація опубліковані в [Sawabob/coffeeflow](https://github.com/Sawabob/coffeeflow). Основна гілка — `main`. Стабільні версії позначаються анотованими тегами та публікуються в розділі Releases.

Для отримання проєкту:

```powershell
git clone https://github.com/Sawabob/coffeeflow.git
cd coffeeflow
```

Інструкції запуску наведено в README. `.gitignore` виключає локальну базу, секрети, залежності та кеші.

## Подальша розробка

Рекомендований процес — GitHub Flow: окрема гілка для зміни, перевірка результату, pull request і злиття в `main`.

```powershell
git switch main
git pull --ff-only origin main
git switch -c feature/frontend
```

Після змін запустіть відповідні тести, зробіть коміт, надішліть feature-гілку та створіть pull request. Порядок архівування описано в `docs/ARCHIVING.md`.
