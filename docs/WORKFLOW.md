# Планування та робота з Git

Ролі наведено як функції в навчальному проєкті; імена учасників команди не задані. При індивідуальному виконанні всі ролі поєднує один виконавець. Оцінки нижче — план, а не журнал фактично витраченого часу.

| Завдання | Критерій готовності | Роль | Орієнтир |
|---|---|---|---|
| Схема SQLite | Таблиці, ключі й обмеження створюються без втрати даних | Back-end | День 1, 2 год |
| Каталог | GET, POST, PATCH, DELETE; захищені зміни | Back-end | День 1, 3 год |
| Адміністративний доступ | Хеш пароля, сесія, CSRF, закриті маршрути | Back-end | День 2, 3 год |
| Замовлення | Серверна ціна, транзакція, час, права доступу, статуси | Back-end | День 2, 4 год |
| Контракт API | Параметри, приклади, помилки, OpenAPI | Документація | День 3, 2 год |
| Тести та звіт | Успішні й негативні сценарії, реальний журнал | Тестування | День 3, 3 год |

Вибрана стратегія — GitHub Flow: стабільна `main`, окрема гілка `feature/<назва>` для кожної зміни, перевірка тестів, pull request і злиття. Це не означає наявності рівно двох постійних гілок: тимчасових feature-гілок може бути декілька.

У робочій папці підготовки ініціалізовано локальний Git-репозиторій `main`. ZIP містить вихідні файли без службової `.git`. Віддалений репозиторій не створено й код не опубліковано: посилання GitHub не вигадується. Для здачі зараз доступні звіт і архів.

## Публікація у власному репозиторії

Створіть у своєму GitHub порожній репозиторій `coffeeflow` (публічний чи приватний відповідно до вимог викладача). Не додавайте README під час створення, якщо надсилатимете цей готовий проєкт. Після розпакування архіву:

```powershell
git init -b main
git add .
git commit -m "Implement CoffeeFlow frontend and API"
git remote add origin https://github.com/YOUR_USERNAME/coffeeflow.git
git push -u origin main
```

Замініть `YOUR_USERNAME` власним логіном. Git може попросити налаштувати ваше ім’я, email і вхід до GitHub. Не використовуйте вигадані облікові дані. `.gitignore` виключає локальну базу, секрети й залежності.

Для наступних змін:

```powershell
git switch main
git pull origin main
git switch -c feature/frontend
```

Після змін запустіть тести, зробіть коміт, надішліть feature-гілку і створіть pull request. У README репозиторію залиште інструкції запуску; у вікно здачі можна прикріпити його справжню адресу.

## Завдання Front-end

Виконано: спільний шаблон і стилі; меню й кошик; оформлення та власні замовлення; адміністративні екрани; обробка помилок; перевірка адаптивності; інтеграційні тести; звіт. Ролі — Front-end, Back-end, тестування й документування — описують функції, а не вигаданих учасників команди.
